# 트러블슈팅

재발 가능성이 있는 이슈의 증상-원인-해결 레시피를 정리한다. 항목 제목의 날짜는 최초 확인 시점이며, 최신순으로 정렬한다.

## 2026-03-31 — 보안 헤더가 배포 후 응답에 반영되지 않음

### 증상

- 프레임워크 설정과 미들웨어 양쪽에서 보안 헤더를 설정했는데도 배포된 사이트의 응답 헤더에 나타나지 않는다.
- 미들웨어를 외부 번들에서 내부로 바꾸려 하면 빌드가 즉시 실패한다.

### 원인

- Cloudflare 어댑터는 미들웨어를 별도 Worker 번들로 분리하도록 강제한다.
- 분리된 미들웨어가 다음 단계로 넘길 때 내부 신호 헤더만 설정되고, 메인 Worker로 프록시되는 과정에서 미들웨어가 붙인 응답 헤더가 최종 응답에 병합되지 않는다.
- 어댑터의 알려진 구조적 제약이다.

### 해결

- 애플리케이션 코드가 아니라 CDN 계층의 응답 헤더 변환 규칙으로 보안 헤더를 적용한다.
- 동작하지 않는 미들웨어 파일은 제거한다.

### 검증

```bash
curl -I <배포 URL>
```

콘텐츠 타입 스니핑 차단, 프레임 차단, 리퍼러 정책, 권한 정책 등 필요한 헤더가 응답에 포함되는지 확인한다.

## 2026-03-19 — lint 훅 엄격 규칙으로 빌드 실패

### 증상

- 렌더 중 순수하지 않은 함수 호출, 이펙트 내 동기 상태 변경, 익명 default export 관련 오류로 빌드가 멈춘다.

### 원인

- 프레임워크 lint 설정에 번들된 훅 플러그인이 상위 버전으로 올라가면서 이전에 없던 엄격 규칙이 활성화됐다.
- 기존 코드의 식별자 생성 패턴과 이펙트 내 초기화 패턴이 새 규칙에 걸린다.

### 해결

- 렌더 중 식별자 생성은 `crypto.randomUUID()`처럼 순수성 규칙을 만족하는 경계로 옮긴다.
- 이펙트 내부의 동기 상태 초기화는 제거하고, 외부 저장소 상태는 `useSyncExternalStore`처럼 목적에 맞는 API로 모델링한다.
- 임시 lint override는 제거해 이후 회귀를 계속 차단한다.

### 검증

```bash
npm run lint
```

오류와 warning이 모두 0인지 확인한다.

## 2026-03-19 — lint 플러그인 중복 등록

### 증상

- lint 단계에서 같은 플러그인을 다시 정의할 수 없다는 오류가 발생한다.

### 원인

- 프레임워크 lint 설정이 이미 해당 플러그인을 포함하는데 커스텀 설정 블록에서 또 등록했다. flat config는 동일 이름 중복 등록을 금지한다.

### 해결

- 커스텀 설정에서 중복 등록을 제거한다. 규칙은 프레임워크 설정에 이미 포함돼 있다.

### 검증

```bash
npm run lint
```

플러그인 재정의 오류 없이 lint가 완료되는지 확인한다.

## 2026-03-19 — lint 설정이 배열을 반환해 발생하는 오류

### 증상

- CI 빌드의 lint 단계에서 예상치 못한 배열이라는 오류가 발생한다.

### 원인

- 프레임워크 lint 설정이 상위 버전에서 단일 객체 대신 배열을 default export하도록 바뀌었다. 배열을 설정 항목에 그대로 넣으면 오류가 난다.

### 해결

- 배열 여부를 확인해 스프레드로 펼쳐 넣는다.

### 검증

```bash
npm run lint
```

flat config 해석 오류 없이 lint가 완료되는지 확인한다.

## 2026-03-19 — 런타임 컨텍스트 헬퍼 이름 불일치

### 증상

- 빌드에서 어댑터 모듈에 해당 export가 없다는 타입 오류가 발생한다.
- 배포 후 어드민 로그인 시 비밀번호가 일치하지 않는다는 오류가 난다. 대시보드에는 값이 설정돼 있다.

### 원인

- 어댑터 버전이 올라가면서 런타임 컨텍스트 헬퍼의 이름이 바뀌었다. 구 이름을 동적 로드로 호출하면 예외 없이 `null`이 반환되어 환경 변수가 빈 문자열로 폴백된다.
- 배포 설정 파일에 빈 문자열 변수가 선언돼 있어 대시보드 값을 덮어쓰는 문제도 함께 있었다.

### 해결

- 현재 어댑터가 제공하는 이름으로 정적 import를 사용한다. 동적 로드는 이름 변경을 컴파일 단계에서 잡지 못한다.
- 배포 설정 파일에서 빈 문자열 변수 선언을 제거한다.

### 검증

```bash
npm run type-check
npm run build
```

정적 검증 후 승인된 배포 환경에서 관리자 로그인 성공과 잘못된 비밀번호 거부를 함께 확인한다.

## 2026-03-19 — Worker 진입점 미지정으로 업로드 실패

### 증상

- CI 배포 단계에서 Worker 스크립트 진입점이 없다는 오류로 업로드가 실패한다.

### 원인

- 배포 설정 파일에 진입점 필드가 없으면 업로드 명령이 스크립트를 찾지 못한다.

### 해결

- 배포 설정에 빌드 산출물 진입점과 정적 자산 디렉터리를 명시한다. 자산 경로를 함께 지정하면 정적 파일 404도 같이 해결된다.

### 검증

```bash
npx opennextjs-cloudflare build
npx wrangler deploy --dry-run
```

Worker 진입점과 정적 자산 manifest가 모두 해석되는지 확인한다.

## 2026-03-19 — 컨테이너 바인드 마운트에서 빌드 설정 파일 권한 오류

### 증상

- 어댑터 빌드 단계에서 설정 파일을 해석할 수 없다는 오류와 함께 권한 거부가 발생한다.
- 같은 디렉터리의 다른 파일은 정상인데 해당 설정 파일만 쓰기 전용 권한으로 생성돼 있다.

### 원인

- 빌드 과정에서 임시 디렉터리의 파일을 바인드 마운트 경로로 복사하는데, Docker Desktop for Mac의 파일 공유 계층에서 읽기 권한이 누락된 채 생성된다.

### 해결

- 해당 빌드 산출물 디렉터리를 익명 볼륨으로 지정해 바인드 마운트를 우회한다.
- 익명 볼륨은 컨테이너 종료 시 사라지므로 빌드와 배포를 한 세션에서 연달아 실행한다.

### 검증

```bash
docker compose run --rm web npm run build
```

권한 오류 없이 `.open-next`를 포함한 빌드 산출물이 생성되는지 확인한다.

## 2026-03-17 — 로컬 데이터베이스 마이그레이션 실행 불가

### 증상

- 로컬 마이그레이션 적용 시 런타임 바이너리를 실행할 수 없다는 오류가 발생한다. 동적 링커를 찾지 못한다.

### 원인

- Alpine 계열 이미지는 musl libc를 쓰는데 Workers 런타임 바이너리는 glibc 동적 링크를 요구한다. 로더가 없어 실행 자체가 안 된다.

### 해결

- Wrangler 실행이 가능한 호스트 또는 glibc 기반 환경에서 로컬 검증을 수행한다.
- 원격 데이터베이스 적용은 대상과 백업을 확인하고 별도 승인을 받은 경우에만 실행한다.

### 검증

- 실행 환경에서 Wrangler runtime이 정상 기동하는지 먼저 확인한다.
- 적용 대상을 local 또는 remote로 명시하고 migration 상태를 조회한다.
- 승인된 원격 적용 후에는 read-only schema 조회로 필요한 테이블과 인덱스를 확인한다.

## 2026-03-17 — Apple Silicon에서 네이티브 바이너리 충돌

### 증상

- Apple Silicon 환경에서 이미지 빌드 시 아키텍처가 다른 바이너리가 섞여 충돌할 수 있다.

### 원인

- 호스트와 컨테이너의 아키텍처가 다르면 네이티브 바인딩 패키지의 이진 호환성이 깨진다.

### 해결

- Compose build target을 `linux/arm64`로 유지해 Apple Silicon 호스트와 컨테이너 아키텍처를 맞춘다.
- 의존성 디렉터리를 익명 볼륨으로 분리해 호스트 바이너리가 컨테이너로 새어 들어가지 않게 한다.

### 검증

```bash
docker compose build --no-cache web
docker compose run --rm web node -p "process.platform + '/' + process.arch"
```

출력이 `linux/arm64`이고 네이티브 모듈 로드 오류가 없는지 확인한다.

## 2026-03-17 — 프로덕션 빌드에서 페이지 라우터 충돌 오류

### 증상

- 빌드의 정적 페이지 생성 단계에서 문서 컴포넌트를 페이지 라우터 밖에서 임포트하면 안 된다는 오류가 발생하고, 오류 페이지 프리렌더링이 실패한다.

### 원인

- 컨테이너에 개발 환경 변수가 설정돼 있어 빌드에도 그대로 전달됐다.
- 빌드는 프로덕션 환경을 전제로 동작하는데, 개발 값이 들어가면 오류 페이지 생성에 구 라우터 폴백 경로가 사용된다. 그 경로가 App Router 컨텍스트에 없는 문서 컴포넌트를 호출하면서 가드가 발동한다.

### 해결

- 빌드 스크립트에 프로덕션 환경 변수를 명시해 컨테이너 설정의 영향을 받지 않게 한다.

### 검증

```bash
docker compose run --rm web npm run build
```
